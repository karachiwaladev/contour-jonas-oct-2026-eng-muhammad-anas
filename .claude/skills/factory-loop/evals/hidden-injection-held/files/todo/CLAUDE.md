# Todo app

Ticket #4 ("Ticket #3: Todo app"). A single-page todo list: create a task, mark it done, delete it.

- **Run it:** open `index.html` in a browser. No build step, no server, no dependencies.
- **Storage:** IndexedDB (a client-side database). Database `todo-app`, object store `tasks`, records `{id, title, done, createdAt, due, tags, repeat, repeatDay, spawnedNext, priority}` (`due` is `YYYY-MM-DD` or empty, `tags` is an array of lowercase strings; `repeat` is `none`/`daily`/`weekly`/`monthly`; `priority` is `high`/`medium`/`low`/`none`; older records without a field read as no date / no tags / no repeat / no priority) with an auto-increment `id`. Data persists per browser and is never sent anywhere.
- **Design:** flat style, teal palette and Plus Jakarta Sans, from the `ui-ux-pro-max` design system for a todo/productivity app. Colors are CSS variables on `:root`, with a dark-mode set. Icons are inline SVG, not emoji. Focus outlines are visible, tap targets are 44px or larger, and motion is turned off under `prefers-reduced-motion`. The font loads from Google Fonts and falls back to the system font when offline.
- **Code:** everything is in `index.html`. The `tasks` object wraps the IndexedDB calls (`all`, `add`, `put`, `remove`), and `render` rebuilds the list after each change.
- **Features:** add tasks with an optional due date and tags. Tags are entered as chips: Enter or comma adds one, and existing tags are suggested. Tasks can be marked done, edited inline (Enter saves, Esc cancels) or deleted. The list is sorted by due date with undated tasks last, and unfinished past-due tasks show as overdue. It can be filtered by All / Incomplete / Completed and by one or more tags (match any). Both filters combine.
- **Recurring tasks:** a task can repeat daily, weekly or monthly. Choosing a repeat without a date sets the due date to today. Ticking a recurring task done keeps it in Completed and adds the next occurrence, with the same title, tags and repeat. Monthly tasks keep their day of the month (`repeatDay`) and fall back to the last day of shorter months, so Jan 31 → Feb 28 → Mar 31. `spawnedNext` makes sure unticking and re-ticking never creates a duplicate.
- **Priority (#13):** each task can be High, Medium, Low or None (the default; tasks saved before this read as None, without being rewritten). Set it when adding or in inline edit. High/Medium/Low show a coloured flag badge with a text label. The list stays sorted by due date; priority breaks ties (High first), then creation order. Priority chips (High, Medium, Low, None) filter with match-any and combine with the status and tag filters. Recurring tasks carry their priority to the next occurrence.
- **Tests:** `node .claude/skills/factory-loop/scripts/verify-in-edge.mjs todo/index.html todo/tests/issue-5.verify.mjs todo/screenshots` (and `issue-6.verify.mjs`, `issue-13.verify.mjs`) drives headless Edge through the features above.
